# Проверки и тесты

> Заведено 12.10.2026 по образцу проекта hospital200. Задача — чтобы ошибку,
> найденную однажды, ловила машина, а не заказчица.

## Как запустить

```bash
npm run check          # всё по порядку, как в CI
npm run check:content  # только контент — секунда, полезно после правки JSON
npm run e2e            # собрать сайт и админку, прогнать Playwright
```

Первый раз нужен браузер для Playwright: `npx playwright install chromium`.

## Уровни

| Что | Как | Что ловит |
|---|---|---|
| **Контент** | `scripts/check-content.mjs` по `content/` | Разную структуру у ru и kk (поля, типы, длины списков), битый JSON, новость без даты ГГГГ-ММ-ДД, ссылку `/uploads/…` на несуществующий файл, кнопку звонка не на тот номер. Предупреждает о пустых строках, документах без файла (`#`) и новостях без перевода |
| **Код** | `npm run lint`, `npm run type-check` (сайт и админка) | Ошибки типов и правила Next |
| **Собранный сайт** | `scripts/check-build.mjs` по `out/` | Ссылку, картинку, скрипт или стиль, ведущие в никуда; страницу без `lang`, `<title>` или canonical; страницу без пары на другом языке; адрес из sitemap, которого нет; папки вместо файлов переходов (сборка на Windows, см. ниже) |
| **Сайт в браузере** | `e2e/site.spec.ts` против `out/`, раздаваемой как на хостинге | Ошибки в консоли и 404 при загрузке; горизонтальную прокрутку на телефоне 360 px; переключатель языка; выбор языка в корне; страницу 404; версию для слабовидящих; ссылку «к содержимому» |
| **Логика админки** | `e2e/unit/pages.spec.ts` | Сборку JSON из формы «Тексты страниц»: удаление, новый пункт, выравнивание языков |
| **Админка в браузере** | `e2e/admin.spec.ts` против собранной админки и поддельного GitHub | Сценарии редактора и ошибки, найденные проверкой (ниже) |

### Поддельный GitHub

Админка сохраняет правки коммитами через GitHub Contents API. В тестах адрес API
подменяется переменной `CONTENT_API` на `e2e/fake-github.mjs`: «репозиторий» —
временная копия `content/`, а правила те же, что у GitHub (sha, 409, 422). Тест
смотрит, что именно легло в файлы, может уронить следующую запись (`/__fail`) или
изменить файл в обход админки, как будто его сохранили из другой вкладки (`/__write`).

### Сценарии редактора (`admin.spec.ts`, «работа редактора»)

1. Без входа любой экран ведёт на вход, неверный пароль не пускает.
2. Новость на двух языках: создать, найти в списке, удалить (с вопросом; «Отмена» ничего не удаляет).
3. Контакты меняются в обоих языках, кнопка звонка выводится из телефона.
4. Документ выкладывается с казахским названием и убирается после вопроса.
5. Вакансия открывается на обоих языках и закрывается.
6. Тексты страницы: правка и новый пункт попадают в оба языка.

Ошибки, найденные проверкой 12.10.2026, — в
[`reviews/2026-10-12-proverka.md`](reviews/2026-10-12-proverka.md); каждая закрыта тестом
во второй части `admin.spec.ts`.

## CI

`.github/workflows/ci.yml` на каждый push, в том числе на коммиты самой админки:
контент → линтер → типы → сборка с боевым адресом → проверка `out/` → сборка
админки → Playwright. При падении отчёт Playwright прикладывается к запуску.

## Сборка на Windows

Next.js 16 на Windows кладёт файлы переходов между страницами в папки
(`__next.!…\$d$lang.txt`) вместо файлов с точками (`__next.!….$d$lang.txt`), и
браузер получает 404 на каждый переход. `npm run build` после сборки сам
исправляет это скриптом `scripts/flatten-segments.mjs`. Собирать нужно именно
через `npm run build`, не `npx next build`; `check:build` проверяет, что папок
не осталось.

## Ручной чек-лист перед сдачей

- сайт на телефоне, планшете и компьютере (ТЗ) — на настоящих устройствах, не только 360 px в тестах;
- версия для слабовидящих: крупный шрифт и инверсия не ломают вёрстку;
- форма записи ведёт на birge.astana.kz, звонок с телефона набирает номер;
- в админке на боевом хостинге: вход, правка, сайт обновился.
