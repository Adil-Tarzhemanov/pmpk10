# Сайт КГУ «ПМПК № 10» акимата города Астаны

Официальный сайт психолого-медико-педагогической консультации: двуязычный
(казахский и русский), с версией для слабовидящих и готовностью к подключению CMS.

Утверждённый заказчицей макет главной страницы лежит в `pmpk10-demo/index.html`
и оставлен как эталон вёрстки. Разбор технической спецификации — в `docs/TZ.md`.

---

## Что под капотом

| Слой | Решение | Почему |
|---|---|---|
| Каркас | Next.js 16, App Router | Статический экспорт, метатеги, sitemap и роутинг из коробки |
| Вывод | `output: "export"` — готовый HTML в `out/` | Серверу не нужен Node: подойдёт любой shared-хостинг |
| Стили | Один файл дизайн-системы `app/globals.css` | Токены, компоненты и версия для слабовидящих в одном месте, разметка стилей не содержит |
| Шрифты | PT Sans и PT Serif через `next/font` | Есть подмножество `cyrillic-ext` с казахскими ә ғ қ ң ө ұ ү һ; шрифты самохостятся, к Google запросов нет |
| Контент | JSON-файлы в `content/` | Их же правит админка; базы данных у сайта нет |
| Админка | Своё приложение в `admin/` | Вход по паролю: редактору не нужен аккаунт на GitHub |

> Про пункт 5 ТЗ («JavaScript без фреймворков»). Требование ТЗ направлено против
> сайтов-конструкторов: WordPress и Tilda в том же пункте названы прямо. Next.js
> не конструктор и не CMS-движок — он собирает статические HTML, CSS и JS, которые
> и уезжают на хостинг. Стек согласован с заказчицей до начала работ, как того
> требует п. 11 ТЗ.

## Разработка

```bash
npm install
npm run dev      # http://localhost:3000 — откроется выбор языка
npm run build    # готовый сайт в out/
npm run lint
```

Корень `/` — страница выбора языка: скрипт смотрит язык браузера и уходит
на нужную версию, без JavaScript видны две кнопки. Работает одинаково
и в `dev`, и в собранном сайте.

**Ошибка в консоли на несуществующем адресе — это нормально.** Любой
односегментный адрес, которого нет (`/en/`, `/admin/`, обычная опечатка),
в режиме разработки попадает в маршрут `/[lang]`, и при `output: "export"`
Next считает это ошибкой:

```
Page "/(site)/[lang]/page" is missing param "/[lang]" in "generateStaticParams()"
```

Относится только к `npm run dev`. В собранном сайте таких адресов нет вовсе,
хостинг отдаёт `out/404.html`. Сборка при этом проходит без ошибок.

## Структура

```
app/
  (chooser)/         корень «/»: развилка языков, свой корневой layout
  (site)/[lang]/     все страницы обеих языковых версий
    layout.tsx       корневой layout: <html lang>, шапка, меню, подвал
    page.tsx         главная
    about/           о нас
    documents/       документы
    news/            новости и страница отдельной новости
    anticorruption/  противодействие коррупции
    vacancies/       вакансии
    contacts/        контакты и карта проезда
  globals.css        дизайн-система целиком
  sitemap.ts         карта сайта с hreflang
  robots.ts          robots.txt
components/          шапка, подвал, панели, карточки
content/             тексты и реквизиты — то, что правит админка
lib/                 языки, словари интерфейса, шрифты, чтение контента
public/uploads/      фотографии, загруженные через админку
admin/               админка: отдельное приложение со своим package.json
```

Групп в скобках в адресах нет: `(chooser)` даёт «/», `(site)` ничего не добавляет.
Корневых layout'ов два, потому что атрибут `lang` у `<html>` должен совпадать
с языком страницы, а задать его можно только там, где этот `<html>` и рисуется.

Главное меню повторяет обязательную структуру из п. 2 ТЗ. Раздела
«Обратная связь» в нём нет: заказчица попросила убрать форму, вопросы
принимаются по телефону и почте со страницы контактов.

## Языки

Обе версии равноправны и живут по своим адресам: `/ru/...` и `/kk/...`.
Отдельные адреса нужны не только для честности, но и для поиска: у каждой
версии свои `title`, `description`, `canonical` и `hreflang`.

Тексты интерфейса — в `lib/dictionary/`, тексты разделов — в `content/`.
Чтобы добавить язык, допишите его в `lib/i18n.ts`, заведите словарь и
языковую папку в `content/`.

**Важно:** имя файла новости в `content/news/ru/` и `content/news/kk/`
должно совпадать. По нему строится адрес, и переключатель языка на странице
новости ищет ровно такой же файл в другой папке.

## Как добавить новость руками, без админки

Создайте два файла с одинаковым именем:

```
content/news/ru/2026-09-15-novyy-grafik.json
content/news/kk/2026-09-15-novyy-grafik.json
```

```json
{
  "date": "2026-09-15",
  "dateLabel": "15 сентября 2026",
  "title": "Заголовок новости",
  "summary": "Одно предложение для карточки на главной.",
  "body": ["Первый абзац.", "Второй абзац."]
}
```

Пересоберите сайт — новость появится в списке, на главной и в `sitemap.xml`.
Сортировка идёт по полю `date`, от свежих к старым.

## Размещение на хостинге

`npm run build` кладёт готовый сайт в папку `out/`. Загрузите её содержимое
в корень сайта на хостинге — больше ничего не требуется: ни Node, ни PHP,
ни базы данных.

Перед сборкой задайте настоящий адрес сайта, иначе `canonical`, `hreflang`
и `sitemap.xml` будут указывать на демо-адрес:

```bash
NEXT_PUBLIC_SITE_URL=https://pmpk10.edu.kz npm run build
```

### Nginx

```nginx
server {
  listen 443 ssl http2;
  server_name pmpk10.edu.kz;
  root /var/www/pmpk10/out;

  # Адреса заканчиваются слешем, каталогам нужен index.html
  location / {
    try_files $uri $uri/ $uri/index.html =404;
  }

  # Корень сразу на нужный язык — быстрее, чем страница выбора
  location = / {
    return 302 /ru/;
  }

  # Страница 404 из сборки. Сейчас это стандартная страница Next.js —
  # оформить её в стиле сайта имеет смысл вместе с логотипом заказчицы
  error_page 404 /404.html;

  # Статика с хешами в имени не меняется — можно кешировать надолго
  location /_next/static/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
  }
}
```

SSL — бесплатный сертификат Let's Encrypt (`certbot --nginx`), обновляется сам.
HTTPS обязателен: без него браузеры помечают сайт как небезопасный, а поисковики
понижают его в выдаче.

### Apache

Положите в корень `.htaccess`:

```apache
RewriteEngine On
RewriteRule ^$ /ru/ [R=302,L]
ErrorDocument 404 /404.html
```

### Vercel или Netlify

Подключите репозиторий, сборка определится сама (`next build`), каталог
публикации — `out`. Редирект с корня добавьте в `vercel.json` или `_redirects`.

## Иллюстрации

Сюжетные картинки — дети на главной и семья на странице «О нас» — взяты
готовыми из **unDraw** (undraw.co) и лежат в `public/illustrations/`.

Лицензия unDraw разрешает использовать их бесплатно, в том числе в
коммерческих проектах, изменять и не указывать авторство. Запрещено:
перепродавать, распространять паками, обучать на них модели и делать из них
интеграции. Ничего из этого мы не делаем, ставить копирайт на сайте не нужно.

Фирменный акцент подставлен вместо исходного фиолетового unDraw:

```
#6c63ff  →  #17708F   (--sky)
```

Остальная палитра иллюстраций не трогалась. Чтобы взять новую картинку,
скачайте SVG с undraw.co, замените этот один цвет и положите рядом.

Мелкая графика — фон героя, иконки направлений работы, значки специалистов,
обложки новостей — нарисована в `components/illustrations.tsx` инлайновым SVG:
она использует переменные темы и сама перекрашивается в тёмной, чего файл
из `public/` не умеет.

**Фотографий на сайте нет намеренно.** Снимков «наших специалистов» или
«детей на приёме» у нас не было, а сгенерированные выдавали бы вымысел за
факт — рядом с карточками состава, подписанными настоящими должностями, это
недопустимо. Иллюстрация ничего не утверждает. Когда заказчица передаст
настоящие фотографии, места под них готовы: обложки новостей и портреты
специалистов.

## Админка

Панель редактирования — отдельное приложение в `admin/`. Редактор входит по
паролю: аккаунт на GitHub ему не нужен, и слова «GitHub» в интерфейсе нет.
Правку панель коммитит в репозиторий своим токеном, хостинг ловит push и
пересобирает сайт — обычно меньше минуты.

В ТЗ названа Decap CMS, и сначала стояла она. От неё пришлось отказаться:
Decap требует у редактора аккаунт на GitHub и OAuth-посредника, а вход по
почте (Git Gateway) объявлен устаревшим. Сотруднику учреждения, которому
нужно добавить новость, это непригодно.

**Сайту сервер не нужен, а админке нужен.** Сайт — статика, встанет на любой
shared-хостинг копированием папки. Админка держит токен репозитория вне
браузера, поэтому ей нужен Node: Vercel, Netlify или VPS. Это стоит учесть
до выбора хостинга — на голом shared-хостинге панель не запустится.

Что правится через панель:

| Экран | Файлы |
|---|---|
| Новости | `content/news/ru/*.json`, `content/news/kk/*.json` |
| Контакты и график | `content/site/ru.json`, `content/site/kk.json` |
| Документы | `content/documents/ru.json`, `content/documents/kk.json` |
| Вакансии | `content/vacancies/ru.json`, `content/vacancies/kk.json` |

Русская и казахская версии правятся на одном экране: у новости обязано
совпадать имя файла, иначе переключатель языка уводит в никуда. К новости
можно приложить фотографию — она уезжает в `public/uploads/`, без неё
карточка получает узор в фирменных цветах.

Остальное — главная, «О нас», противодействие коррупции — правится в
JSON-файлах руками. Это сотни полей, и универсальный редактор на них вышел
бы неудобнее обычного текстового файла.

**Запуск:**

```bash
cd admin
npm install
cp .env.example .env.local   # заполнить по подсказкам внутри файла
npm run dev                  # http://localhost:3100
```

Переменные описаны в `admin/.env.example`: пароль хранится хешем scrypt,
токен репозитория — fine-grained, только на этот репозиторий, право
Contents: Read and write. На хостинге те же переменные задаются в его
панели и в репозиторий не попадают.

**Что проверено, а что нет.** Вход, разграничение доступа (без входа все
четыре экрана уводят на `/login`) и вёрстка — проверены. Чтение и запись
контента не исполнялись ни разу: для этого нужен настоящий токен
репозитория, а его у проекта пока нет. Первое, что стоит сделать после
выдачи токена, — добавить через панель тестовую новость и удалить её.

## Карта проезда

Подложка — встраиваемая карта OpenStreetMap: без ключа API, без аккаунта и
без платы за показы. На статическом хостинге это единственный вариант,
который переживёт смену подрядчика и не отвалится, когда у кого-то кончится
квота. Счётчики Google и Яндекса на страницу контактов при этом не попадают.

2ГИС, Яндекс и Google подключены обычными ссылками «построить маршрут»:
родитель открывает маршрут в привычном приложении, а трекеры загружаются
только после клика, уже на их стороне.

Точка задаётся координатами в `content/site/*.json` и правится через CMS:

```json
"geo": { "lat": 51.1697416, "lon": 71.3791755, "zoom": 17, "verified": false }
```

Пока `verified: false`, рядом с адресом висит метка «точка на карте
уточняется». Снимать её после того, как заказчица подтвердит, что пин стоит
на нужном здании. Координаты берутся на openstreetmap.org: правая кнопка по
зданию → «Показать адрес».

## Версия для слабовидящих

Включается кнопкой в верхней панели. Даёт увеличение шрифта до 150 %,
чёрно-белую и инверсную цветовую схемы, отключение декоративной графики.
Выбор запоминается в браузере — человеку, которому нужен крупный шрифт,
не приходится включать его заново на каждой странице.

В ТЗ этот пункт стоит «по согласованию», но для государственных сайтов
Казахстана он фактически обязателен, поэтому сделан сразу.

## Что ещё нужно от заказчицы

Всё, чего у нас нет, помечено на сайте бейджем «уточняется» — их видно
глазами, искать по коду не нужно.

- Точный юридический адрес, телефоны, WhatsApp, эл. почта
- ФИО, должности и фотографии специалистов
- Логотип или герб в векторе (сейчас стоит временная эмблема)
- Пакет нормативных документов в PDF
- Точное юридическое наименование и БИН
- Желаемое доменное имя (в ТЗ по ошибке указан `rgurpo.kz` из чужого документа)
- Координаты для карты 2ГИС
